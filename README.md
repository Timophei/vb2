# vb2 — бот-консультант по сценарию состояний

PHP 8.3 + SQLite + OpenAI. Вторая версия визового бота: вместо одного большого промта — **движок, который исполняет сценарий** (JSON): состояния, слоты, переходы, действия в Битрикс24, таймеры. Сценарий загружается и правится в админке, версии хранятся.

Ставится на тот же сервер, что v1 (Ubuntu 24.04, nginx, PHP 8.3-FPM), отдельным поддоменом `vb2.b-integration.ru`, в `/var/www/vb2`. С v1 ничего общего: своя папка, своя база, свой Telegram-бот.

## Как устроен ход

```
сообщение клиента
  → событие client_message            (closed → greeting, postponed → возврат)
  → КЛАССИФИКАТОР (модель, строгий JSON): intent + слоты из реплики
  → движок: слоты записаны → переходы (сначала global_transitions, потом состояния),
            цепочкой: jobs → jobs_finish → closed; при переходе on_exit / on_enter / таймеры
  → ОТВЕТЧИК (модель): промт собирается из global_prompt_rules + goal/instruction/forbidden
            состояния + известные/недостающие слоты + каталог + база знаний разделов состояния;
            инструменты — только из "tools" состояния (счёт, анкета, биометрия)
  → события от инструментов (invoice_sent) → снова переходы
```

**Переходы решает код, а не модель.** Модель только разбирает реплику и пишет текст. Поэтому бот не может «выставить счёт из визы», а в карточке диалога видно, почему он оказался в этом состоянии.

**Сумму счёта считает код** по каталогу: (цена варианта + опции) × участники. Пустая цена — бот говорит «уточнит менеджер» и счёт не выставляет.

**Счёт в тестовом режиме:** у счёта порядковый номер (№ 0001…), бот присылает QR-код (qrencode) со ссылкой на демо-страницу оплаты. Сканируете телефоном → «Оплатить (демо)» или «Ошибка оплаты» → бот сам продолжает диалог.

## Структура

```
vb2/
├── config.example.php      → скопировать в config.php
├── scenarios/              сценарий и каталог по умолчанию (грузятся в базу при первом запуске)
├── engine/
│   ├── engine.php          ход, условия, переходы, шаблоны {{…}}, слоты
│   ├── llm.php             классификатор и ответчик (+ инструменты)
│   ├── actions.php         действия: Битрикс24, уведомления; инструменты: счёт, анкета, биометрия
│   ├── timers.php          таймеры состояний
│   └── scenario.php        версии сценария, проверка
├── lib/                    база, клиенты/диалоги, база знаний, каталог, Telegram, Битрикс24, вход в админку
├── public/                 единственная папка, доступная из интернета
│   ├── index.php, widget.js  веб-чат во весь экран / виджет для чужого сайта
│   ├── api/chat.php        API веб-чата
│   ├── telegram.php        вебхук Telegram
│   ├── pay.php             страница оплаты (пока демо)
│   └── admin/              админка

└── deploy/                 nginx, systemd, update.sh
```

## Установка

```bash
# 1. Пакеты (если ещё нет после v1)
sudo apt install -y git poppler-utils qrencode fonts-dejavu-core php8.3-sqlite3 php8.3-curl php8.3-mbstring php8.3-zip php8.3-xml php8.3-gd

# 2. Код
sudo git clone https://github.com/Timophei/vb2.git /var/www/vb2
cd /var/www/vb2
sudo cp config.example.php config.php
sudo nano config.php        # ключ OpenAI, токен Telegram, вебхук Битрикс24, public_url

# 3. Права
sudo mkdir -p data && sudo chown -R www-data:www-data data && sudo chmod 770 data
sudo chown root:www-data config.php && sudo chmod 640 config.php

# 4. nginx + HTTPS
sudo cp deploy/nginx-vb2.conf /etc/nginx/sites-available/vb2
sudo ln -s /etc/nginx/sites-available/vb2 /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d vb2.b-integration.ru

# 5. Воркер таймеров (напоминания, ожидание оплаты, «отложено»)
sudo cp deploy/vb2-worker.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now vb2-worker

# 6. Telegram-вебхук (новый бот от @BotFather; токен и secret — из config.php)
curl "https://api.telegram.org/bot<ТОКЕН>/setWebhook" \
  -d "url=https://vb2.b-integration.ru/telegram.php" \
  -d "secret_token=<telegram_secret>"

# 7. Проверка всего сразу
sudo -u www-data php bin/check.php
```

Откройте `https://vb2.b-integration.ru/admin/` — при первом входе админка предложит создать администратора.

## Обновление

```bash
sudo bash /var/www/vb2/deploy/update.sh
```

`config.php` и `data/` (база, файлы) в git не хранятся и при обновлении не трогаются. Сценарий и каталог живут в базе — правки из админки не теряются.

## Админка

- **Песочница** — чат «как клиент» + справа всё о диалоге: состояние, слоты (обязательные подсвечены), таймеры, переходы, действия, что ушло в модель. Кнопки: событие (оплата прошла / не прошла / менеджер взял…), «прошло N минут» (таймеры), перейти в состояние, записать слот, сброс. В Битрикс24 песочница **не пишет** — в журнале видно, что ушло бы (можно включить кнопкой, если `bitrix_mode = live`).
- **Диалоги** — все диалоги с фильтром по состоянию и каналу; карточка такая же, как в песочнице, плюс ответ от имени менеджера (бот встаёт на паузу по правилу сценария).
- **Сценарий** — схема состояний, список незаполненного (TODO), редактор JSON с проверкой, загрузка файла, версии. Каждый диалог помнит свою версию; в карточке его можно перевести на активную.
- **Каталог** — карточки товаров: варианты (тарифы) с ценами и сроками, опции с надбавками, «цена за заказ / за участника», кто продаёт (бот или менеджер), текст для бота, параметры (период регистрации DV, акция).
- **Материалы** — база знаний **по разделам**: `general`, `visa/general`, `visa/<страна>`, `cards`, `green_card`, `jobs`. Состояние ищет только в своих разделах (`knowledge` в сценарии). Таблица показывает, какие разделы сценарий ждёт и какие пусты.
- **Настройки** — приветствие, кнопки-подсказки, состояние системы и **справочник Битрикс24**: права вебхука, стадии лидов, воронки и стадии смарт-процесса — чтобы вписать коды в `settings.hr` сценария.

## Битрикс24

Входящий вебхук (права **crm**; для будущих открытых линий — ещё imbot, imopenlines, im) → `bitrix_webhook` в config.php.

- `bitrix_mode => 'dry'` (по умолчанию) — ничего не отправляется, в журнале действий видно, что ушло бы. Начинайте с него.
- `bitrix_mode => 'live'` — пишет по-настоящему: для диалогов с сайта и из Telegram бот создаёт лид при первой записи в CRM.

Поля в действиях сценария со значением `TODO…` пропускаются с пометкой в журнале — сценарий можно запускать недозаполненным. Слоты без своего поля Б24 пишутся текстом в «Комментарий» лида, отдельным блоком `=== Бот vb2 ===`, который обновляется на месте и не трогает заметки менеджеров.

**HR-воронка** (состояния `jobs` → `jobs_finish`): вакансия → название лида, ФИО → поля имени, контакт → телефон/e-mail, резюме → таймлайн лида, элемент смарт-процесса 1038 со связью с лидом, лид → стадия `UC_IGWO64` (последней — чтобы при ошибке лид не ушёл в провал пустым). Ошибка в любом шаге → диалог уходит менеджеру.

**Сделки и контакты** (вкладка «Битрикс24» → «Направления»): для визы, карт, Green Card можно вести не лид, а **контакт + сделку**. Сделка создаётся, когда понятен продукт и известен контакт клиента (или дошли до счёта / передачи менеджеру). Контакт сначала ищется по телефону и e-mail среди существующих (найденный не правится), иначе создаётся. Для каждого направления: воронка, стадия при создании, стадии по этапам бота (например «Ожидание оплаты» → «Заключение договора и оплата»), значение поля «Услуга», ответственный. Сумма счёта → сумма сделки.

**Поля** сопоставляются отдельно для лида, сделки и контакта с существующими полями портала. Списки заполняются по совпадению текста (классификатор получает варианты списка и называет значение точно); нет в списке — «Другой / Другая», исходное значение — в комментарий. Там же — проверка **обязательных полей** и значения по умолчанию для тех, что бот не заполняет.

С портала данные читаются только по кнопке «Загрузить с портала».

Открытые линии подключим после теста в веб-чате.

## Сценарий: справка по JSON

- `states.<имя>.type`: `conversation` (разговор), `transit` (пишет одно сообщение и сразу дальше), `waiting` (ждём события), `terminal` (закрыто). После `terminal` новый круг начинается с чистыми слотами (контакты остаются: `settings.keep_slots_on_restart`) и новым лидом.
- Условия переходов (`on`): `slot`+`eq`, `slot_set`, `slot_not`, `slots_complete: "required"`, `any: [...]`, `intent`, `event` (+`count_gte`), `counter`+`gte`, `always`. Несколько ключей — «И».
- Переход в то же состояние не повторяет `on_enter` (не дублирует уведомления).
- Шаблоны: `{{slot}}`, `{{jobs.full_name.last}}`, `{{settings.hr.lead_status_id}}`, `{{lead.id}}`, `{{x | default: 'текст'}}`.
- Действия: `say` (`text` — готовый текст; `from: instruction` — пишет модель по инструкции этого состояния), `b24_update_lead` (`fields`: объект или `"slots:visa.*"` / `"slots:all"`), `b24_attach_resume`, `b24_create_smart_item`, `openline_finish`, `notify_manager`. У действия может быть `if` (условие). У состояния — `on_error`.
- Таймеры: `after_minutes` или `at_slot`, `start_on: "bot_answered_question"` (перезапуск после каждого ответа), `condition`, `max_fires`, `action: {say | event}`.
- Интенты: `intents.list`; описания для классификатора можно задать в `intents.descriptions`.

## Важное

- Бот собирает персональные данные (имя, телефон, резюме). По 152-ФЗ нужна политика обработки ПД: ссылка в `privacy_url`, она появится под чатом.
- Бэкап — копия папки `data/` (база `vb2.sqlite`, загруженные файлы).
- Файлы от клиентов (резюме) — до `max_upload_mb` (15 МБ), лежат в `data/uploads/`.
